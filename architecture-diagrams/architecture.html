DeepSeek Harness 系统架构

构建在 vendored Cordis 插件框架之上的 agent harness:模型适配器、工具注册表、会话日志、甚至 agent loop 本身,都是配置里可替换的插件行。扩展 DSH 的方式不是 patch 核心,而是在旁边挂一个自己的插件。

everything is plugin · no privileged core

2Everything is Plugin:组合机制

3Turn / Step 生命周期(agent-loop)

一个 step = 一次模型请求 + 它调用的工具;一个 turn = 零或多个 step:第一个输入被认领前开,不再欠任何东西时关。

turn/start 持久事件
认领 inbox 输入 + 排队消息;组装 prompt sections + 工具 schema。输入通过唯一 inbox:有些消息立即唤醒,注入的上下文等下一条消息。
agent/pre-step waterfall
决定模型看到什么:可改写认领的消息,或直接拒绝。拒绝 / 首次改写为空 → 零 step 关闭 turn(日志仍记录这次尝试)。
step/start → user/message 持久事件
进入的消息落日志;从日志派生模型历史。
agent/request → llm/stream waterfall
请求瀑布可补 provider/model;流式响应产生 assistant/chunk* → assistant/message(持久)。
tools/pre-execute → tools/execute → tools/post-execute waterfall ×3
工具执行管道;结果落日志 tool/call* / tool/result*(持久)。
step/end 持久事件
工具欠另一个请求,或有新输入到达 → 认领 → 下一个 step(循环回到 agent/pre-step)
agent/turn-stopping serial · 无 next
有序决策点,监听器可停 turn。
turn/end 持久事件
turn 关闭;turn/* step/* user/message assistant/* tool/* 全部落日志。
铁律:Model-visible ⟺ logged。任何到达模型请求的内容必须能从会话日志重建,有运行时断言保证。新增模型可见输入 = 新增一个 session 事件(SessionEventMap 声明合并)。

5Cordis 事件分发模式

模式await顺序返回值用途
emit否注册顺序观察无观察事实(如 session/event)
waterfall否注册顺序有around 中间件,必须调 next() 否则短路
parallel是并行无扇出
serial是注册顺序有有序决策(agent/turn-stopping)

三个事件域 —— 选对域是大多数改动的第一个决策

Session 事件 · 持久事实append 进日志并经 session/event 广播。事实必须在 reload 后存活 → 用它。
Agent 事件 · agent/*携带存活 Agent:inbox、step、状态、请求、校验、续跑。观察/拦截进行中的工作 → 用它。
Capability 事件把策略和适配器挂到缝上(fs/* tools/* telemetry/*),无需 import loop。

6Session 日志:事件溯源

单一权威源:一切模型可见内容、UI、持久化、fork/resume、telemetry 都从这条流派生。

append-only SessionEvent 日志
turn/* · step/* · user/message · assistant/chunk* · assistant/message · tool/call* · tool/result* …
deriveMessages()投影模型历史
UI / transcript渲染自 session/event
持久化插件订阅 event,flush 时落盘(JSONL/SQLite)
fork / resumectx.sessions.fork(source, boundary?)
telemetry镜像日志记录
  • 原始 assistant/chunk 事件保留,保证 replay 与 UI 保真。
  • 事件用 TS 声明合并扩展 SessionEventMap;required-on-read 默认,ignorable: true 例外;只有结构性格式变化才 bump SESSION_FORMAT_VERSION。
  • 持久化是插件自己的事:JSONL / SQLite 后端订阅 session/event,在 session/flush 时排水。

7行为该加在哪(扩展点速查)

新行为挂在已文档化的扩展点上;改 loop 本身必须更新架构文档。

目标机制
加模型 provider在 ctx.llm 上注册适配器
加模型可见能力注册到 ctx.tools;schema 自动进 prompt 组装
给某会话不同能力集组 agent preset;service 行需 isolate realm
拦截请求/工具/turn用 agent/* 或 tools/* 事件;agent/turn-stopping 停 turn
加模型可见上下文agent.inject(),落在下一个被接纳的请求
加人类命令注册 ctx.commands,不经模型 turn 直接分发
加后台工作注册 ctx.jobs;job_* 工具收集/停止
加持久会话状态扩展 SessionEventMap;从日志渲染和 replay
限定注册到单个 agent用那个 agent 的 agent.ctx
让 agent 自我改造extensions/:实时检查/挂载/卸载自己的插件
